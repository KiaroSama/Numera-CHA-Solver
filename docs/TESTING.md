# Testing and evidence

Confirmed seams: native SDK/CLI, authenticated HTTP/tasks/review, real model/device, MCP HTTP/stdio bridge, owned dashboard, desktop and installed distribution. Synthetic workers prove ownership behavior only, never OCR accuracy.

## Hosted-only delivery validation

Version0.4.0 is built/tested on GitHub-hosted Windows x64, Ubuntu24.04 x64 and Apple Silicon macOS. Only manual dispatch triggers the native matrix; no local/self-hosted runner is used. Local builds and general suites remain excluded. The later explicit installation request permits only current-host activation and GPU checks that hosted CPU cannot establish. Source formatting/config syntax inspection does not count as execution evidence.

Each job first checks the portable plugin schema identity/allowed fields, native compatibility manifests and canonical skill payload, then exercises duplicate executable discovery and fail-closed dependency notice selection (unknown version, mismatched license/revision and altered bytes). The discovery placeholders are never executed. Packaging verifies all omitted notice texts and includes unchanged preferred source for every MPL-covered dependency; missing or mismatched catalog entries block delivery.

Each job uses two compiler workers, one test thread and one model operation. Native tests have their own async/process deadlines; the captured outer command owner supplies wall/idle/tree cleanup. Stable libtest has no universal per-case kill timeout. Job wall limit is45min; each stage records exit status and duration. Genuine timeouts/failures block package upload, not waived by retries or disabled assertions. Native suite summaries and bounded redacted failure sections are surfaced in CI logs; a missing result capture fails validation. POSIX discovery does not read an already-owned PID/create-time identity's environment again after exec/exit. New candidates receive a refreshed, identity-validated parent-chain/adoption check, including after denied inspection. On Darwin only, a denied environment read while the kernel reports `SIDL` (process creation) receives at most one second of identity-preserving observation, capped by the existing command deadline. Initialization never confers ownership: normal ancestry/tag checks still follow, and a persistently initializing or inaccessible live unknown process fails closed. Unknown ended processes are excluded; known ended children are reaped with nonblocking positive-PID waits, without consuming the root's exit status. An executing orphan remains a failure, and a live unattributed same-user process with inaccessible ownership evidence still blocks the run. No OS security settings are weakened.

## Required tiers

- Source-generated JSON/binary conformance: arithmetic, SDK, HTTP status/body/security headers, geometry, owner assessment, CTC, preprocessing and request digests. Expectations remain generated from the historical Python source, not target translations. Rust additionally pins fixture hashes and all mapped native targets; the retired historical implementation is no longer executed or restored. Installed persistence/restart checks use real native CLI/HTTP/TaskStore behavior.
- Native lifecycle/negative cases: bounded config/input/files/model integrity, download ownership/crash, redaction, credentials/socket/root collision, task idempotency/TTL/restart/overload, decoder and worker cancellation/reap/successor. The standalone worker fixture is compiled once in CI and supplied through `NUMERA_FIXTURE_WORKER_EXECUTABLE`.
- New public boundaries: MCP initialize/list/call/auth/host/origin/input and bridge failure/protocol/cleanup; manual correction/confirm/cancel/expiry/stale terminal state, Unicode scalar/control limits, exact TTL bounds, retained capacity and competing database connections; native runtime names and POSIX credential modes. Download regressions cover cancellation/deadline lease release, immutable validation after an apparently successful transport and refusal of directory/symlink lock paths without altering their contents. Unsupported external input is rejected and human confirmation is not an agent tool.
- Actual device: official CPU ONNX Runtime1.31.0 and immutable owned ASCII image on every hosted OS. Exact answer/input-shape and `server_verified=false` asserted. Hosted CPU evidence is not a skipped CUDA pass; legacy CUDA tests remain a separate explicitly selected hardware tier.
- Browser/distribution: isolated headless dashboard auth/arithmetic/manual review/mobile/reduced-motion on each OS; native Linux installed desktop WebDriver/Xvfb smoke; Windows launcher ownership/native persistence and restart; native package/source/license/hash/private inclusion checks. Windows/macOS native GUI interaction and trusted signing/notarization are not claimed from headless browser/build tests.

## Evidence interpretation

The 45 historical source function dispositions in `tests/fixtures/parity/source-tests.json` map to implemented native coverage; the original generation markers are historical metadata. They are not a pass receipt for later changes. [Validation](../reports/VALIDATION.md) records exact-revision execution evidence. Test counts, timings, compiler results and synthetic recognition do not measure real CAPTCHA accuracy, cross-version performance improvements or full Rust line coverage.

The Rust Linux native WebDriver executable sends explicit keep-alive to the driver's separate upstream connection pool, while closing each client socket after a bounded response. `tests/native_webdriver.rs` exercises the same transport on every hosted OS; `examples/native_webdriver.rs` exercises the real installed Linux GUI. `examples/installed_release.rs` checks the delivered CLI/connector and actual CPU OCR with isolated private model state. Their three Python predecessors were retired after the replacement native matrix passed on all three hosted platforms, including actual Linux GUI shutdown and installed CPU OCR. The preserved historical Git revision remains the migration reference, not an additional product runtime. It does not use urllib's forced close header or retry uncertain commands. Hosted real-socket contracts check the header, socket closure, UTF-8, HTTP/tool failures, oversize/malformed responses and a dropped connection before the actual GUI tier.

Linux native close is requested through a hosted-only Rust/Xlib fixture that verifies the app PID, executable, process birth and unique closeable window before sending `WM_DELETE_WINDOW`. WebDriver's WebKit page close is not treated as native application exit; actual backend drain remains required. The accepted download-control socket explicitly uses blocking I/O with its existing read deadline on BSD/macOS.

A release-promotion job depends on every native platform. It checks all six archives, exact source/manifests, every file size/hash and publication exclusions before a manually promoted GitHub Release after default-branch integration. Promotion reuses the exact successful run's assets without rebuilding; no automatic CI triggers are enabled. Remote draft asset digests are checked before publication; existing versions are not overwritten.

## Language boundary

The application core, CLI, HTTP/MCP servers, model worker and Tauri shell are Rust. Historical Python fixture generation and rollback witnesses, their frozen environment restoration and the obsolete migration runner are retired at the owner's request. Immutable generated fixtures remain unchanged and are exercised by native tests; live cross-language rollback is no longer claimed. `examples/hosted_rollback.rs` verifies installed native persistence/restart/idempotency without Python. The real headless Chrome dashboard and POSIX process supervision/regressions are also Rust; no tracked Python files or Python validation prerequisites remain. The source mapping keeps its immutable provenance while resolving the old browser target to the native dashboard executable. The HTML/CSS/JavaScript webview and PowerShell Windows launchers retain their platform roles. Language inventory is source size, not line coverage or a passing test receipt; no generated padding or Linguist overrides are used.

Required real labeled CAPTCHA/audio/provider fixtures are unavailable; no live provider acceptance or new accuracy claim is made. Models/user data/operational logs/shared tools survive cleanup. Disposable hosted runner work/cache is job-contained, and project-owned old self-hosted installation/registration is removed separately after inspection.
